# RootOut — Design Spec

Date: 2026-07-10
Status: Approved for implementation (autonomous session; owner spec in goal)

## What

RootOut is a free, open-source, minimalistic macOS deep app uninstaller — the
AppCleaner model: pick an installed app, RootOut finds every file the app left
across the system (support files, caches, preferences, containers, launch
agents, logs…), and moves the app plus its leftovers to the Trash.

One job, done well. No cleaner suites, no menubar helpers, no analytics, no
network access at all.

## Constraints (from owner)

- Name: **RootOut**
- Minimal & modern UI, **Liquid Glass** theme, like a native modern macOS app
- **Apple Silicon (arm64) only**
- Free & open source, hosted at `github.com/TonmoyBishwas/RootOut-mac`
- Distributed as a **DMG** on GitHub Releases so non-technical users can install
- No bloat: the app does exactly what its name says

## Decisions

| Decision | Choice | Why |
|---|---|---|
| UI framework | SwiftUI | Native, minimal code, first-class Liquid Glass |
| Min macOS | 15.0 (Sequoia), real `.glassEffect()` on macOS 26+ | Every M-series Mac can run it; genuine Liquid Glass where the OS supports it, `.ultraThinMaterial` glass fallback on 15 |
| Architecture | arm64 only | Owner requirement |
| Build system | Swift Package (exe + core lib) + `Scripts/build-app.sh` assembling `RootOut.app`, `hdiutil` DMG | No `.pbxproj` to maintain; fully scriptable & CI-able; reproducible |
| Deletion | `FileManager.trashItem` (recoverable), admin fallback via `osascript` for root-owned files | Safety first: nothing is permanently destroyed by RootOut itself |
| Signing | Ad-hoc codesign; README explains first-launch (right-click → Open) | No paid Developer ID available; standard for free OSS apps |
| License | MIT | Maximal openness |

## Architecture

Two targets in one Swift Package:

1. **RootOutCore** (library, unit-tested) — no UI:
   - `AppInventory`: enumerates installed apps from `/Applications`,
     `~/Applications` (skips system/Apple apps by bundle ID prefix
     `com.apple.` and anything under `/System`).
   - `LeftoverScanner`: given an app's bundle ID + name, finds related files
     in the known locations (user & local domain):
     `Application Support`, `Caches`, `Preferences` (incl. lockfiles),
     `Containers`, `Group Containers`, `Saved Application State`, `Logs`,
     `LaunchAgents`/`LaunchDaemons`, `HTTPStorages`, `WebKit`, `Cookies`,
     `Application Scripts`, crash reports (`DiagnosticReports`), receipts.
     Matching is conservative: exact bundle-ID match first; name-based match
     only for unambiguous names (≥ 4 chars, not a dictionary-common word list,
     exact directory-name match). Never matches inside another app's container.
   - `Uninstaller`: terminates the running app (NSRunningApplication),
     trashes selected items, reports per-item success/failure; failed
     root-owned items optionally removed via one admin-privileged `/bin/rm`
     invocation (user sees exactly which paths, and must confirm).
   - `SizeCalculator`: async directory sizes for display.
2. **RootOut** (executable) — SwiftUI app:
   - Single window. Left: searchable app list (icon, name, version, size).
     Right: scan results for the selected app — checkbox list grouped by kind
     (App, Support, Caches, Preferences, …) with sizes and a total, and one
     **Uninstall** button.
   - Liquid Glass: translucent window (behind-window material), glass cards
     and controls via a small `glass()` view-modifier helper
     (`.glassEffect()` on macOS 26+, material fallback on 15).
   - Confirmation dialog before trashing. Result toast after.

## Safety rules (non-negotiable)

- Never list or touch Apple/system apps (`com.apple.*`, `/System/**`).
- Never operate on RootOut itself.
- Everything goes to the Trash, never `rm` — except the explicit,
  user-confirmed admin fallback for the exact listed root-owned paths.
- Scanner only returns paths inside its whitelisted leftover directories.

## Error handling

- Scan errors (unreadable dirs, permission denied) are skipped silently —
  a missing leftover is acceptable; a wrong deletion is not.
- Trash failures surface per-item in the results view; app keeps running.
- If the app to uninstall is running, RootOut asks, then force-terminates.

## Testing

- Unit tests on `RootOutCore` (`swift test`): scanner matching (positive +
  negative/collision cases, e.g. app "Notion" must not match "Notes"),
  bundle-ID candidates, safety filters (Apple apps excluded, path whitelist).
  Filesystem tests run against a temp-dir fixture tree, not the real system.
- Manual end-to-end: install a disposable fixture app, uninstall it with the
  built RootOut.app, verify app + leftovers land in Trash.

## Distribution

- `Scripts/build-app.sh`: release build (arm64), assemble `RootOut.app`
  (Info.plist, icns generated by `Scripts/make-icon.swift`), ad-hoc codesign.
- `Scripts/make-dmg.sh`: DMG with `RootOut.app` + `/Applications` symlink.
- GitHub release `v1.0.0` with the DMG attached; README has plain-language
  install steps for non-technical users (including the Gatekeeper
  right-click → Open step for unsigned apps).

## Out of scope (no bloat)

Orphan/leftover-only scanning, duplicate finders, startup managers, updaters,
menubar extras, telemetry, preferences window, onboarding screens.
